# Card field proposal

20 October 2026. These fields are demonstrated in the corrected standalone HTML preview; integration into the live SQL render packet and production card renderer remains pending. The user permits either centred or side-aligned branding. The corrected HTML uses a compact company logo at top-left, pass type at right and a small GatePass signature at the bottom.

All cards: name, photo, opaque QR, actual visit office/location, validity date/time and a compact pass reference. Keep 85.6 × 54 mm landscape and the QR quiet zone. Approval status and guard assignments remain in the guard application.

Standalone preview spacing refinement: related details use tighter vertical groups, host name and host Employee ID are kept together, VALID FROM / VALID UNTIL use two stacked rows, and the photo box is shortened to 156 × 176 viewBox units. QR remains 208 × 208 units with its existing quiet zone. Real photo integration must preserve the image aspect ratio rather than stretching it to fit.

| Card type | Additional proposed fields |
|---|---|
| Employee project visit | Employee ID, assigned projects summary, requested project where needed and short purpose |
| Employee Digital ID | Employee ID, assigned projects summary and short standard Digital ID reason |
| External visitor | Host name with corporate employee ID, plus short purpose |

Purpose/reason should be a brief useful label, such as Meeting, Training or Forgot ID, fitting one or two readable lines. Preserve the detailed submitted explanation in the authorized application instead of crowding the small physical card with free text. Use the trusted submitted/directory data; never accept arbitrary print-body identity or destination overrides.

Assigned projects are the employee's trusted directory memberships and may include several projects; use readable short names/codes on the small card and retain full current details in the guard app. Do not invent one primary project. A project visit's requested destination is a separate field and does not attest approval. Printed membership is not a substitute for current server authorization.

For visitors, host name helps reception and guard staff more than an unexplained ID alone. Use the host's corporate employee ID rather than an internal database UUID or SSO identifier. Do not print host email/phone merely to fill space.

Adding these fields to the live render path will require a forward SQL contract change for trusted employee/project/host/purpose fields, followed by service projection, layout and print/readability validation. The corrected standalone HTML and matching PNG are generated by tools/build-redesigned-card-preview.ts in output/previews. Its synthetic QR values are independently decoded but never issued into SQL. It prints at 85.6 × 54 mm with separate employee/visitor print buttons; physical printer acceptance remains pending.
